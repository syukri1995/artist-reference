⚡ Fix N+1 query issue in WorkspaceManager load_state

💡 **What:**
Optimized `WorkspaceManager.load_state` to replace an N+1 query pattern with a single, batch SQL IN query. Instead of running a query for each missing image ID, the updated code gathers all missing file paths, dedupes them, and runs a batched lookup in chunks of 900 (avoiding SQLite limits).

🎯 **Why:**
The old implementation executed one `SELECT id FROM images WHERE file_path = ?` for every item in the workspace state without an `image_id`. On larger workspaces (e.g., 5,000 to 10,000 items), this drastically slowed down the loading time, causing blocking delays on the UI thread when starting up or changing workspaces.

📊 **Measured Improvement:**
In synthetic benchmarks tested locally on a 10,000-item dataset:
- Baseline (Before): ~6.8 to 6.9 seconds
- Optimized (After): ~0.12 seconds
- Overall Speedup: >50x faster when resolving many items.
